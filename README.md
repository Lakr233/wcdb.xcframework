# wcdb.xcframework

Use prebuilt [WCDB](https://github.com/Tencent/wcdb) XCFrameworks with Swift Package Manager.  
Use WCDB without compiling its C/C++ core. The binaries include prebuilt SQLCipher.

| Platform           | Architectures    | Minimum Deployment Target |
|--------------------|------------------|---------------------------|
| macOS              | x86_64 arm64     | 10.13                     |
| Mac Catalyst       | x86_64 arm64     | 13.0                      |
| iOS                | arm64            | 12.0                      |
| iOS Simulator      | x86_64 arm64     | 12.0                      |
| tvOS               | arm64            | 12.4                      |
| tvOS Simulator     | x86_64 arm64     | 12.4                      |
| watchOS            | arm64 arm64_32   | 6.0                       |
| watchOS Simulator  | x86_64 arm64     | 6.0                       |
| visionOS           | arm64            | 1.0                       |
| visionOS Simulator | arm64            | 1.0                       |

The manifest uses Swift tools 6.2, so consumers need Xcode 26 or later.

## Usage

Add this package to your `Package.swift` dependencies:

```swift
.package(
    url: "https://github.com/Lakr233/wcdb.xcframework",
    from: "2.1.16"
)
```

Then add `wcdb.xcframework` as a dependency for your target:
```swift
.target(
    name: "MyApp",
    dependencies: [
       .product(name: "WCDBSwift", package: "wcdb.xcframework"),
       // or
       .product(name: "WCDBObjc", package: "wcdb.xcframework"),
    ]
)
```

## Building

`Script/platforms.sh` is the single source of truth for the platform slices. The
release workflow builds each slice in a GitHub Actions matrix, then merges them
into `WCDBSwift.xcframework` and `WCDBObjc.xcframework`.

To build one slice locally:

```bash
git clone --depth 1 --branch v2.1.16 https://github.com/Tencent/wcdb.git /tmp/wcdb
(cd /tmp/wcdb && git submodule update --init --recursive --depth 1)

# visionOS needs the upstream project patched first; the script is idempotent.
python3 Script/patch-upstream.py /tmp/wcdb

DERIVED_DATA_PATH=/tmp/wcdb-deriveddata \
  ./Script/build-platform.sh /tmp/wcdb WCDBSwift visionos build/archives

DERIVED_DATA_PATH=/tmp/wcdb-deriveddata \
  ./Script/build-platform.sh /tmp/wcdb WCDBObjc visionos build/archives
```

Merge a complete set of archives and validate every slice:

```bash
./Script/merge-xcframework.sh build/archives build/xcframeworks
```

The merge step refuses a missing archive and runs
`Script/verify-xcframework.py`, which checks that all ten slices carry the
expected platform, architectures, and minimum OS version. CI then runs
`Script/test-imports.sh`, which compiles a one-line consumer against every
slice, so a framework that cannot be imported fails before publication.

Release binaries are built with the default Xcode on the `macos-latest`
GitHub runner (Xcode 26.6 at the time of writing). `Script/platforms.sh` pins
every deployment target, so a newer Xcode cannot raise them silently. When a
new default Xcode stops supporting one of them, the build or the verify step
fails; raise it in `Script/platforms.sh`, `Script/verify-xcframework.py`,
`Script/test-imports.sh`, `Package.swift.template`, and the table above.

Xcode 26 installs the tvOS, watchOS, and visionOS platforms on demand. Without
them the generic destinations do not resolve, so install them before building
those slices locally:

```bash
xcodebuild -downloadPlatform tvOS
xcodebuild -downloadPlatform watchOS
xcodebuild -downloadPlatform visionOS
```

`Package.swift` is generated by the release workflow from
`Package.swift.template`; edit the template when changing products or targets.
